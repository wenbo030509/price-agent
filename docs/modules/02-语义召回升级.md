## 一、模块定位

### 1.1 当前链路（代码级走读）

`tools/semantic_search_tool.py → semantic_product_search()` 的执行流程：

```
Step 1: query_all_products_parallel()
    → PlatformParallelAgent 并行查 4 平台
    → 返回所有平台的商品列表（约 50 条）

Step 2: 去重
    → 同名商品保留最低价（best_by_name dict）

Step 3: _passes(item) 规则硬过滤
    → category == "手机"                          # 精确匹配
    → budget_max >= item.price                    # 范围过滤
    → brand == item.brand                         # 精确匹配
    → processor_brand == item.processor_brand      # 精确匹配
    → performance_tier == item.performance_tier    # 精确匹配
    → use_case_tags 字符串 contains 每个 tag       # 标签包含匹配

Step 4: _value_score(item) 排序
    → TIER_SCORE / price * 10000  （hardcoded）

Step 5: 返回 top-N
```

**关键问题**：

用户说"拍照效果好的手机" → `_passes()` 取 `use_case_tags` 字符串，检查是否 contains `"photography"`。但如果用户说"拍照效果好"（没带 photography 这个英文 tag），或者"夜拍""自拍""人像"，就完全匹配不上。同理，用户说"跟 iPhone 15 差不多的安卓机"，"差不多"无法翻译成任何规则条件。

**根本原因**：规则过滤强依赖关键词精确命中，没有语义相似度的容错空间。

### 1.2 目标链路

```
Step 1: query_all_products_parallel()                           # ← 不变
Step 2: 去重                                                     # ← 不变
Step 2.5: build_product_text() — 拼接 embedding_fields           # ← 新增
Step 2.6: 向量召回 — query embedding × product embeddings        # ← 新增
          → 召回 top-K_vector 个候选（K=50，覆盖全量也 OK）
Step 3: _passes(item) 规则硬过滤                                  # ← 保留
         过滤范围 = 向量召回结果 ∪ 全量商品
Step 4: 两路融合去重                                              # ← 新增
Step 5: _value_score() 排序                                       # ← 不变
Step 6: 返回 top-N
```

**核心思路**：向量召回扩大候选池（语义相关的都能进），规则过滤保证精确性（不符合硬条件的剔除）。两路互补，不互相替代。

### 1.3 不改什么

- `semantic_product_search()` 的函数签名和 OpenAI function schema
- `query_all_products_parallel()` 接口
- `_passes()` 和 `_value_score()` 的逻辑
- Agent 层：`_react_loop` 和 `_plan_and_execute` 对该工具的使用方式不变

## 二、方案设计

### 2.1 向量化策略

#### 2.1.1 商品文本构造

从行业 Config 读取 `embedding_fields`，拼接为一个文本：

```python
def build_product_text(product: dict, fields: list) -> str:
    """
    将商品的结构化字段拼接为一段自然语言文本，用于 embedding。

    手机示例：
    "商品名：iPhone 15 Pro 黑色 256GB
     品牌：Apple
     处理器：A17 Pro
     描述：A17 Pro芯片，钛金属机身，专业摄像
     场景标签：gaming, photography, flagship, business"
    """
    parts = []
    field_labels = {
        "product_name": "商品名",
        "description": "描述",
        "use_case_tags": "场景标签",
        "processor": "处理器",
        "brand": "品牌",
    }
    for field in fields:
        value = product.get(field)
        if value:
            label = field_labels.get(field, field)
            # use_case_tags 是 JSON 数组字符串，转为可读文本
            if field == "use_case_tags":
                try:
                    tags = json.loads(value) if isinstance(value, str) else value
                    value = ", ".join(tags)
                except (json.JSONDecodeError, TypeError):
                    pass
            parts.append(f"{label}：{value}")
    return "\n".join(parts)
```

#### 2.1.2 Embedding 模型

使用火山引擎 `doubao-embedding-vision-251215`，2048 维。调用方式通过已实现的 `config/embedding.py → EmbeddingClient`：

```python
from config import Settings
client = Settings().embedding_client
vec = client.embed_text("iPhone 15 Pro")          # 单条，返回 np.ndarray
vecs = client.embed_texts(["文本1", "文本2"])      # 批量并行，返回 List[np.ndarray]
```

注意：`/embeddings/multimodal` 端点将多个输入融合为单个向量，因此 `embed_texts()` 内部用 ThreadPoolExecutor 逐条并行调用，行为和批量一致。

#### 2.1.3 向量存储方案

当前商品总量约 50 条（mock），真实数据上线后预估单品类 5000-50000 条。

| 方案 | 适用规模 | 依赖 | 说明 |
|------|---------|------|------|
| A: 内存 numpy | < 10K 条 | numpy | 最简单，mock 阶段足够 |
| B: SQLite + 向量扩展 | < 100K 条 | sqlite-vec | 与现有 SQLite 技术栈一致 |
| C: ChromaDB | 任意 | chromadb | 最标准的轻量向量库 |

**推荐分两步**：
- **Phase 1（mock 验证期）**：方案 A（内存 numpy）。50 条商品在内存做 cosine similarity 毫秒级，零依赖。验证召回效果后再换存储。
- **Phase 2（真实数据上线后）**：方案 C（ChromaDB）。标准向量库，支持持久化、metadata 过滤、增量更新。

#### 2.1.4 向量召回流程（Phase 1 内存方案）

```python
def _vector_recall(
    query: str,
    products: list,
    embedding_fields: list,
    embedding_client,            # ← config.embedding.EmbeddingClient
    top_k: int = 50,
) -> list:
    """
    向量召回。
    前提：product 上已有 _embedding 缓存（由 init_product_embeddings 预热）
    1. 对 query 做 embedding
    2. 计算与每个 product 的 cosine similarity
    3. 返回 top-K
    """
    import numpy as np
    
    query_vec = embedding_client.embed_text(query)
    
    scores = []
    for product in products:
        p_vec = product.get("_embedding")
        if p_vec is None:
            # 未预热 → 实时计算（兜底，不应发生）
            text = build_product_text(product, embedding_fields)
            p_vec = embedding_client.embed_text(text)
            product["_embedding"] = p_vec
        
        similarity = np.dot(query_vec, p_vec) / (
            np.linalg.norm(query_vec) * np.linalg.norm(p_vec)
        )
        scores.append((similarity, product))
    
    scores.sort(key=lambda x: x[0], reverse=True)
    return [p for _, p in scores[:top_k]]
```

**优化点**：
- 商品 embedding 在平台 DB 初始化后一次性预热并缓存到 `product["_embedding"]`
- 后续查询只计算 query embedding，不再重复计算商品 embedding
- 内存方案：50 条商品 × 2048 维 × float32 ≈ 400KB，完全可接受

### 2.2 混合召回策略

向量召回结果 + 规则过滤结果 → 合并去重 → 排序。

**注意**：`_passes()` 当前签名是 `_passes(item: Dict) -> bool`，从闭包读取过滤参数。M2 不改它的签名，而是在 `semantic_product_search()` 外层控制：依据 `enable_vector_recall` 决定是先向量召回再过滤，还是直接规则过滤。这样做对现有 `_passes()` 零侵入。

```python
# 在 semantic_product_search() 内部：

# Step 1-2: 聚合 + 去重（不变）
all_products = ...   # query_all_products_parallel → 去重

# Step 3: 召回
industry_config = _get_industry_config()  # 见 2.5 节
enable_vector = industry_config.get("enable_vector_recall", False)

if enable_vector:
    # 向量召回 → 扩大候选池
    embedding_fields = industry_config.get("embedding_fields", [])
    embedding_client = _get_embedding_client()
    vector_results = _vector_recall(
        query, all_products, embedding_fields, embedding_client, top_k=50
    )
    # 向量结果再过规则过滤（只保留满足硬条件的）
    candidates = [item for item in vector_results if _passes(item)]
    # 补充：规则命中但向量未命中的（按 product_name 去重）
    rule_results = [item for item in all_products if _passes(item)]
    seen = {item.get("product_name") for item in candidates}
    for item in rule_results:
        if item.get("product_name") not in seen:
            seen.add(item.get("product_name"))
            candidates.append(item)
else:
    # 纯规则（与改动前一致）
    candidates = [item for item in all_products if _passes(item)]
```

**去重 key 只用 `product_name`**：因为 Step 2 已同名保留最低价，不会再出现同名重复。

### 2.3 向量索引预热

商品 embedding 在平台 DB 初始化后一次性预热并缓存，后续查询不再重复计算。

```python
# platforms/parallel_agent.py 中新增

_cached_products_with_embeddings: list = []


def init_product_embeddings(industry_config: dict, embedding_client):
    """
    对所有平台的商品预计算 embedding 并缓存。
    调用时机：init_all_platforms() 之后调用一次。
    """
    embedding_fields = industry_config.get("embedding_fields", [])
    if not embedding_fields:
        return
    
    agent = PlatformParallelAgent()
    result = agent.query_all_products_parallel()
    
    all_products = []
    for platform_id, data in result.get("results", {}).items():
        platform_name = data.get("platform_name", platform_id)
        for p in data.get("products", []):
            p["_platform_name"] = platform_name
            all_products.append(p)
    
    if not all_products:
        return
    
    # 逐条 embedding（multimodal 端点特点），内部并行
    texts = [build_product_text(p, embedding_fields) for p in all_products]
    embeddings = embedding_client.embed_texts(texts)
    
    import numpy as np
    for i, product in enumerate(all_products):
        product["_embedding"] = np.array(embeddings[i], dtype=np.float32)
    
    agent._cached_products_with_embeddings = all_products


def get_cached_products():
    """获取已预热的产品列表（含 _embedding）"""
    agent = PlatformParallelAgent()
    return getattr(agent, "_cached_products_with_embeddings", [])
```

**app.py 中的初始化顺序**：

```python
# app.py → initialize()
init_all_platforms()           # 1. 初始化平台 DB
init_parallel_agent()           # 2. 初始化并行查询 Agent
init_product_embeddings(        # 3. 预热 embedding（在 platform DB 就绪后）
    settings.industry_config,
    settings.embedding_client,
)
```


### 2.4 industry_config 获取通道

`semantic_search_tool.py` 是工具函数，需要获取 `industry_config` 和 `embedding_client`。通过模块级缓存 + Settings 懒加载实现：

```python
# tools/semantic_search_tool.py

_industry_config = None
_embedding_client = None


def _get_industry_config() -> dict:
    global _industry_config
    if _industry_config is None:
        from config import load_industry_config
        _industry_config = load_industry_config("mobile")
    return _industry_config


def _get_embedding_client():
    global _embedding_client
    if _embedding_client is None:
        from config import Settings
        _embedding_client = Settings().embedding_client
    return _embedding_client
```

设计理由：
- 工具函数不在 ReActAgent 生命周期内，无法通过 `self.industry_config` 获取
- 模块级懒加载：首次调用时从 `config` 加载并缓存，后续直接返回
- `Settings().embedding_client` 同样懒加载，不会在 import 时触发 API 调用

# tests/eval_m2_recall/test_recall.py

RECALL_TEST_CASES = [
