# Module 4: 生成式推荐

> 在现有推荐链路中引入 LLM 能力：LLM 意图分解替代关键词映射，LLM Rerank 替代 hardcoded 权重排序。
> 推荐结果从"列表"升级为"有推理、有解释的结构化推荐"。

---

## 一、模块定位

### 1.1 当前链路（代码级走读）

用户说"推荐游戏手机 5000 以内"时的完整链路：

```
app.py → POST /api/chat
  → agent.run(query)
    → _detect_intent("推荐游戏手机 5000 以内")
      → USE_CASE_TRIGGER_MAP 命中 "游戏" → has_use_case=True
      → "以内" → has_budget=True
      → "推荐" → has_recommend_word=True
      → has_recommend_trigger=True, model_count=0
      → return "recommendation"

    → _react_loop(user_query, intent_hint="recommendation")
      → System prompt 带 intent_hint，引导 LLM 选 semantic_product_search
      → LLM 手动构造参数：semantic_product_search(use_case="gaming", budget_max=5000)
          ↑ 这里 LLM 需要从自然语言提取参数，不稳定

    → semantic_product_search() 执行
      → 规则过滤 → hardcoded 排序 → 返回列表

    → LLM 综合回答
      → "为您找到以下游戏手机：1. 小米14 ¥3999..."
      → 只有排名和价格，没有推荐理由
```

**三个核心问题**：

1. **参数提取不稳定**：LLM 在 ReAct 循环中"手动"从自然语言提取 tool 参数。用户说"去青海旅游拍照好"，LLM 可能传 `use_case="旅游"`（不在合法枚举值中），导致召回失败。
2. **排序无推理**：`_value_score()` 是 hardcoded 的 `TIER_SCORE / price * 10000`，不理解"游戏手机优先看处理器和散热"这种场景化的排序偏好。
3. **无推荐解释**：只列排名和价格，不说"为什么"，用户无法建立信任。

### 1.2 目标链路

```
用户 Query: "推荐游戏手机 5000 以内"

Stage 1: Intent Decompose（LLM 专用 Prompt）
  输入：用户原始 query
  输出：结构化筛选条件
  {"use_case": "gaming", "budget_max": 5000, "category": "手机"}

Stage 2: Multi-path Recall（M2 增强后的 semantic_product_search）
  输入：Stage 1 输出的结构化条件
  输出：top-20 候选商品

Stage 3: LLM Rerank + Explain（专用 Prompt）
  输入：用户原始 query + 候选商品列表
  输出：重排序 + 逐条推荐理由 + 最佳选择/性价比之选标注
```

### 1.3 不改什么

- `_detect_intent()` 的分类逻辑
- `_react_loop()` 的执行流程（意图分解在工具内部完成，Agent 不感知）
- `semantic_product_search` 的工具签名（新增的都是 optional 参数）
- 前端展示

## 二、方案设计

### 2.1 Stage 1: 意图分解

#### 2.1.1 设计决策

**方案 A**：在 `_react_loop()` 中增加一个分解步骤——Agent 先调 LLM 分解意图，再调工具。
**方案 B**：在 `semantic_search_tool` 内部做分解——工具收到 `raw_query` 参数时内部调 LLM 分解。

**选择方案 B**。理由：
- 对 Agent 层透明，Agent 仍然只需调一个工具
- 工具内部的 LLM 调用不受 ReAct 的 max_round 限制
- 参数提取是工具的内部优化，不应该暴露给 Agent 的思考链

#### 2.1.2 实现

在 `semantic_product_search()` 新增一个 optional 参数 `raw_query`：

```python
def semantic_product_search(
    # ... 现有参数不变 ...
    use_case: str = "",
    brand: str = "",
    processor_brand: str = "",
    # ...
    
    # 新增 optional 参数
    raw_query: str = "",          # 原始用户 query，传入则触发 LLM 分解
    enable_rerank: bool = False,  # 是否开启 LLM Rerank（Stage 3）
) -> Dict:
```

当 `raw_query` 不为空时：

```python
if raw_query:
    conditions = _decompose_intent(raw_query)
    # conditions 覆盖未指定的参数（LLM 已提取的才覆盖，用户显式传的保留）
    if not use_case and conditions.get("use_case"):
        use_case = conditions["use_case"]
    if budget_max is None and conditions.get("budget_max"):
        budget_max = conditions["budget_max"]
    if not brand and conditions.get("brand"):
        brand = conditions["brand"]
    # ... 其他字段同理
```

#### 2.1.3 分解 Prompt

从行业 Config 读取 `prompts.decompose`：

```python
def _decompose_intent(raw_query: str) -> dict:
    """LLM 将模糊需求分解为结构化筛选条件"""
    from config.industry_loader import get_industry_config
    
    prompt_template = get_industry_config("mobile", "prompts", {}).get("decompose", "")
    if not prompt_template:
        return {}
    
    prompt = prompt_template.format(query=raw_query)
    
    # 使用轻量模型（model_parse 或 model_react 均可）
    from config import Settings
    settings = Settings()
    resp = settings.client.chat.completions.create(
        model=settings.model_parse,  # 轻量模型，解析任务不需要强推理
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        max_tokens=300,
    )
    
    raw = resp.choices[0].message.content.strip()
    raw = raw.strip("`").lstrip("json").strip()
    
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        return {}
```

#### 2.1.4 Agent 如何传 raw_query

Agent 在 ReAct 循环中调用 `semantic_product_search` 时，如果当前轮次的 query 是推荐型意图，LLM 将原始 query 作为 `raw_query` 参数传入。System prompt 中新增指引：

```markdown
### 工具5: semantic_product_search

**新增参数 raw_query**：当用户需求是模糊的推荐型查询时（如"推荐游戏手机"、"适合拍照的"），
将用户原始问题传入 raw_query，工具内部会自动分解为精确筛选条件。
如果用户给出了明确的筛选条件（如 use_case="gaming"），则正常传入对应参数，不需要 raw_query。
```

### 2.2 Stage 3: LLM Rerank + Explain

#### 2.2.1 触发条件

当 `enable_rerank=True` 且候选商品数量 > 0 时，在 `_value_score()` 排序之后执行 LLM Rerank。

默认关闭（`enable_rerank=False`），通过行业 Config 的 `enable_llm_rerank` 控制。

#### 2.2.2 实现

```python
def _llm_rerank(
    query: str,
    candidates: list,         # _value_score() 排序后的 top-20
    industry_config: dict,
    top_n: int = 5,
) -> list:
    """LLM Rerank：理解用户需求 → 重排序 → 生成推荐理由"""
    
    prompt_template = industry_config.get("prompts", {}).get("rerank", "")
    if not prompt_template:
        return candidates[:top_n]
    
    # 格式化候选商品为 LLM 可读文本
    candidates_text = _format_candidates_for_rerank(candidates)
    
    prompt = prompt_template.format(query=query, candidates=candidates_text)
    
    from config import Settings
    settings = Settings()
    resp = settings.client.chat.completions.create(
        model=settings.model_synthesize,  # 用综合模型，需要强推理
        messages=[{"role": "user", "content": prompt}],
        temperature=0.3,
        max_tokens=1200,
    )
    
    raw = resp.choices[0].message.content.strip()
    raw = raw.strip("`").lstrip("json").strip()
    
    try:
        result = json.loads(raw)
        return result.get("recommendations", candidates[:top_n])
    except json.JSONDecodeError:
        return candidates[:top_n]


def _format_candidates_for_rerank(candidates: list) -> str:
    """将候选商品列表格式化为 LLM 可读文本"""
    lines = []
    for i, item in enumerate(candidates):
        lines.append(
            f"[{i+1}] {item['product_name']} | "
            f"品牌:{item.get('brand','')} | "
            f"价格:¥{item['price']} | "
            f"平台:{item.get('_platform_name','')} | "
            f"处理器:{item.get('processor','')} | "
            f"性能:{item.get('performance_tier','')} | "
            f"电池:{item.get('battery','')}mAh | "
            f"描述:{item.get('description','')}"
        )
    return "\n".join(lines)
```

#### 2.2.3 LLM Rerank vs 规则排序

LLM Rerank 不替代规则排序，而是作为补充：

- **规则排序**（`_value_score()`）始终执行，保证基线质量
- **LLM Rerank** 是可选增强，开启后在规则排序的 top-20 上做重排 + 生成理由
- 如果 LLM Rerank 失败（JSON 解析异常），自动降级到规则排序结果

#### 2.2.4 Rerank Prompt 设计要点

从行业 Config 读取 `prompts.rerank`，核心要素：
1. 手机评估维度和权重（从 `recommend_dimensions` 动态注入）
2. 用户原始需求
3. 候选商品列表（格式化后）
4. 输出 JSON 格式约束
5. 要求给出"最佳选择"和"性价比之选"

### 2.3 集成点：semantic_product_search 完整流程

```python
def semantic_product_search(
    use_case: str = "",
    brand: str = "",
    processor_brand: str = "",
    performance_tier: str = "",
    budget_max: Optional[float] = None,
    budget_min: Optional[float] = None,
    category: str = "手机",
    sort_by: str = "value",
    top_n: int = 5,
    # ── M4 新增参数 ──
    raw_query: str = "",
    enable_rerank: bool = False,
) -> Dict:
    
    # ── M4 Stage 1: 意图分解 ──
    if raw_query:
        conditions = _decompose_intent(raw_query)
        use_case = use_case or conditions.get("use_case", "")
        brand = brand or conditions.get("brand", "")
        # ... 覆盖未显式指定的参数
        enable_rerank = enable_rerank or conditions.get("needs_rerank", False)
    
    # ── Step 1-2: 聚合 + 去重（不变）──
    agent = _get_agent()
    result = agent.query_all_products_parallel()
    # ... 去重 ...
    
    # ── M2: 向量召回 + 规则过滤 ──
    industry_config = _get_industry_config()
    if industry_config.get("enable_vector_recall"):
        candidates = _hybrid_recall(raw_query or "", candidates, filters, industry_config)
    else:
        candidates = [item for item in candidates if _passes(item, filters)]
    
    # ── 排序 ──
    candidates.sort(key=lambda x: _value_score(x, sort_by), reverse=True)
    
    # ── M4 Stage 3: LLM Rerank ──
    final_enable_rerank = enable_rerank or industry_config.get("enable_llm_rerank", False)
    if final_enable_rerank and len(candidates) > 0:
        reranked = _llm_rerank(
            query=raw_query or use_case,
            candidates=candidates[:20],  # top-20 送去 rerank
            industry_config=industry_config,
            top_n=top_n,
        )
        top_items = reranked
    else:
        top_items = candidates[:top_n]
    
    # ── 格式化返回（兼容现有格式 + 新增 rerank 理由）──
    # ...
```

- [ ] 意图分解准确率 Decompose Accuracy ≥ 0.85
