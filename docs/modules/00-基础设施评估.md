## 二、Embedding 模型方案对比

当前项目用 DeepSeek API（OpenAI 兼容），但 DeepSeek 不提供 Embedding 模型。需要选一个 Embedding 方案。

### 方案对比

| | 方案 A：火山引擎 | 方案 B：OpenAI | 方案 C：本地 bge-large-zh |
|---|---|---|---|
| 模型 | doubao-embedding | text-embedding-3-small | BAAI/bge-large-zh-v1.5 |
| API | 火山引擎 Ark | api.openai.com | 无（本地运行） |
| 维度 | - | 1536 | 1024 |
| 成本 | 可能有免费额度 | $0.02/1M tokens | 免费 |
| 新 API Key | 已有（视觉模型在用 ARK） | 需要 OpenAI Key | 不需要 |
| 新依赖 | 无 | 无（都走 openai SDK） | `sentence-transformers` (~1.3GB 模型) |
| 中文效果 | ★★★★ | ★★★ | ★★★★★ |
| 延迟 | ~100ms | ~200ms | 本地 <50ms |
| 适用规模 | 任意 | 任意 | < 100K 条 |

### 确定方案：火山引擎 doubao-embedding-vision-251215

理由：
1. **复用已有基础设施** — 项目已经在用火山引擎 ARK（视觉模型），同一套 API Key
2. **中文效果优秀** — 豆包 embedding 中文语义理解好
3. **轻量封装** — 用 `requests` 直接调 HTTP API，不依赖 OpenAI SDK
4. **mock 验证期够用** — 50 条商品 + ~50 个知识 chunk，成本近乎为零

**已实现**：`config/embedding.py` — `EmbeddingClient` 封装了 ARK Embedding API 的调用。

```python
from config.embedding import EmbeddingClient

client = EmbeddingClient(
    api_key="your_ark_api_key",
    model="doubao-embedding-vision-251215",
)

# 单条
vec = client.embed_text("iPhone 15 拍照好")

# 批量
vectors = client.embed_texts(["文本1", "文本2", ...])

# 大批量自动分批（每批 50 条，ARK 限制 64）
vectors = client.embed_batched(large_text_list, batch_size=50)
```

API 端点：`POST https://ark.cn-beijing.volces.com/api/v3/embeddings/multimodal`

请求格式（text-only）：
```json
{
    "model": "doubao-embedding-vision-251215",
    "encoding_format": "float",
    "input": [
        {"type": "text", "text": "iPhone 15 Pro 拍照旗舰"},
        {"type": "text", "text": "小米14 骁龙8Gen3 游戏手机"}
    ]
}
```

备选：如果火山引擎 embedding 不可用，降级到本地 `sentence-transformers`（`BAAI/bge-large-zh-v1.5`），一台机器就能跑，不依赖外部 API。

## 三、向量存储方案对比

### 需求分析

| 场景 | 数据量 | 查询频率 | 持久化 | 更新频率 |
|------|--------|---------|--------|---------|
| M2 商品向量 | ~50 条 → 5 万条 | 每次搜索 | 随商品库更新 | 低频 |
| M3 知识 chunk | ~50 个 → 500 个 | 每次知识检索 | 随知识库更新 | 极低频 |

### 方案对比

| | 方案 A：numpy 内存 | 方案 B：ChromaDB | 方案 C：LanceDB |
|---|---|---|---|
| 类型 | 内存数组 | 嵌入式向量库 | 嵌入式向量库 |
| 持久化 | 否（重启丢失） | 是 | 是 |
| 新依赖 | `numpy` | `chromadb` | `lancedb` |
| 安装复杂度 | 极低 | 低（pip install） | 极低（pip install） |
| 适用数据量 | < 1 万条 | 任意 | 任意 |
| 查询速度 | 极快（内存） | 快 | 快 |
| 过滤能力 | 手动 | 内置 metadata filter | 内置 SQL filter |

### 推荐：两阶段策略

**Phase 1（mock 验证期）— 方案 A：numpy 内存**

商品向量和知识 chunk 向量都在内存。理由：
- 50 条商品 × 1536 维 × float32 × 2（商品+知识）= ~600KB，完全可忽略
- 零新依赖（`numpy` 是 Python 生态标配）
- 代码最简单：直接用 `EmbeddingClient` + numpy

```python
from config.embedding import EmbeddingClient
import numpy as np

query_vec = client.embed_text(query)

**Phase 2（真实数据上线后）— 方案 B：ChromaDB**

当商品量突破 1 万条或知识 chunk 突破 500 个时，切换到 ChromaDB。理由：
- 持久化——embedding 不需要每次启动重算
- Metadata filter——按 category、brand、platform 等字段过滤，不用自己写
- 生态最成熟——文档全，社区大，与 LangChain/LlamaIndex 集成好

切换时只需换底层存储实现，向量召回的接口不变：

```python
# Phase 1
class RecallEngine:
    def _vector_search(self, query_vec, top_k):
        # numpy 方案
        return self._numpy_search(query_vec, top_k)

# Phase 2：同一接口，换实现
class RecallEngine:
    def _vector_search(self, query_vec, top_k):
        # ChromaDB 方案
        return self._chroma_search(query_vec, top_k)
```

## 五、汇总

### mock 验证期（Phase 1）最小基础设施

```
Embedding 模型：doubao-embedding-vision-251215（火山引擎 ARK）
Embedding 客户端：config/embedding.py（已实现，requests + numpy）
新增 包依赖：numpy, requests
新增 数据源：knowledge/mobile/ 下 ~20 个 .md 文档
向量存储：numpy 内存（零新依赖）
```

### 真实数据期（Phase 2）升级

```
Embedding：不变（火山引擎 ARK 或切 OpenAI）
向量存储：numpy → ChromaDB（pip install chromadb）
知识库：.md 文档 → 可接入爬虫自动更新
```

### 不需要的基础设施

- **不需要独立向量数据库服务器**（如 Milvus/Pinecone/Qdrant）—— 单品类商品量在 5 万以内，嵌入式 ChromaDB 完全足够
- **不需要新的 API 服务** —— Embedding 复用火山引擎 ARK，LLM 复用 DeepSeek
- **不需要 GPU** —— Embedding 模型走 API（非本地推理），LLM 也走 API
